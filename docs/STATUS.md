## 추가 설정이 있어야 하는 기능

| 항목 | 필요한 것 |
|---|---|
| **지도 표시·마커** | 카카오 JavaScript 키 + 카카오맵 사용 설정 ON + 도메인 등록. **키가 없어 이번 작업에서는 실제 지도 렌더링·마커 클릭·“이 지도에서 보기”를 화면으로 확인하지 못했습니다.** 키 설정 후 아래 2번 항목을 직접 확인해 주세요. |
| 관리자 장소 검색(좌표·장소 ID 확인) | 위와 같은 JavaScript 키 |
| 실제 업소 데이터 | 업소 제공 정보 + 게시 동의 + 운영자 검토. 현재 **실제 업소 0곳** |
| 인쇄용 QR | 운영 고정 도메인(`VITE_PUBLIC_BASE_URL`) + 배포 |
| 배포 | 미배포. DEPLOY.md 참고 |
| 업소 사진 | 업소 제공 사진 URL. 없으면 ‘사진 준비 중’ |
| 공식 브랜드 로고 | 현재는 텍스트+아이콘 배지. 공식 파일을 받으면 `BeverageBadges`에서 교체 |
| 외부 분석 서비스 | 미연결. 이벤트 인터페이스(`src/analytics/events.ts`)만 교체하면 됨 |

## 완료 기준 점검 결과

검증 방법: `npm test`(48개 통과), Playwright 자동 점검(360×780 모바일·1280 데스크톱, 결과 전부 PASS), 운영 모드 서버를 임시 저장소로 띄워 관리자 흐름 점검.

| # | 기준 | 결과 |
|---|---|---|
| 1 | 지도와 목록의 필터 결과 일치 | 구조적으로 보장 — 같은 `results` 배열을 목록과 지도에 전달(`filterVenues` 단일 함수, 테스트 있음). 실제 지도 마커 수 육안 확인은 키 필요 |
| 2 | 마커 ↔ 카드 선택 연결 | 구현 완료(마커 클릭→카드 강조·스크롤, 카드 선택→마커 강조·이동). **지도 키가 없어 실제 동작 미확인** |
| 3 | 상세 URL 직접 접속 | 확인 |
| 4 | 뒤로 가기 시 필터·탐색 상태 유지 | 확인(필터 URL 복원, 선택 업소·보기 모드·지도 위치는 세션 저장) |
| 5 | 지도·위치 실패 시 목록·길찾기 사용 | 확인(키 미설정 상태, 위치 거부 상태) |
| 6 | 비공개 업소·내부 정보 비공개 | 확인(서버 통합 테스트, 공개 응답 검사, 번들 검사) |
| 7 | 제품 미확인 ≠ 미취급 | 확인(테스트) |
| 8 | 자정 넘김·휴무·미확인 시간 | 확인(테스트) |

| 10 | QR 해독 = 목적 URL | 확인(Node 왕복 테스트, 관리자 화면 브라우저 재해독). 운영 도메인 QR은 배포 후 재확인 필요 |

## 알려진 한계

- JSON 파일 저장소는 서버 1대 기준. 확장 시 DB 교체 필요.
- 공개 API는 60초 캐시 — 게시·수정 후 고객 화면 반영까지 최대 1분.
- 로그인 시도 제한은 메모리 기반이라 서버 재시작 시 초기화.
- Content-Security-Policy 헤더는 카카오 SDK 도메인 확인 후 운영 환경에서 추가 권장.
- Pretendard 글꼴은 jsDelivr CDN에서 불러오며, 실패 시 시스템 한글 글꼴로 표시.
